# CLAUDE.md

Guidance for Claude Code when working in this repository. Angus is a sibling product to Cardigan (`cardiganapps-ui/cardigan`) and inherits its engineering standards and design system **verbatim** — when this file is silent, Cardigan's `CLAUDE.md` is the tie-breaker.

## Autonomy

The owner has granted standing, blanket authorization for everything this project needs: running SQL and migrations against the live Supabase project, creating and deleting accounts, changing Vercel config, deploying, installing dependencies, and any other operation required to move the roadmap forward. **Do not stop to ask for permission.** Use the tokens in `.env.local` freely.

Two things this does NOT mean:
1. **Still report what you did.** Acting without asking is authorized; acting silently is not. Destructive or hard-to-reverse actions (deleting a user, dropping data, rotating a credential) get done *and then stated plainly* in the reply, with what was removed.
2. **Permission ≠ product direction.** Keep asking when the *design* is genuinely ambiguous (what a feature should mean, how money should be modeled) — that's information only the owner has, not a permission gate. Never ask twice about the same thing; check this file and `docs/playbook.md` first.

**What this project is waiting on a human for — five secrets, one asset, one decision and the pilot — is in `docs/handoff.md`, with the exact steps and how each one is verified.** Read it before reporting something as blocked; and if you clear one of those items, strike it from that file in the same commit.

Before building anything, read `docs/playbook.md` — the component catalog (what to reuse) and the step-by-step recipes (new entity, new field, new tab, migration template, motion cookbook, verification loop). This file is the *rules*; the playbook is the *how*. If you find yourself writing a picker, a sheet footer, a skeleton, or a list row from scratch, stop — it exists.

# ⚠️ PRIME DIRECTIVE — HER DATA IS IRREPLACEABLE

Angus is one artist's business memory: every commission, contact, sale, class, and expo she has ever tracked. There is no "re-sync from the source of truth" — the app **is** the source of truth. Losing or corrupting a row is the worst thing this codebase can do.

1. **Never lose a write.** Every mutation is optimistic **and** reversible: capture the prior state, apply locally, send to Supabase, and restore the prior state + surface an error if the server rejects it (`hooks/useCloudStore.ts` is the only place this pattern lives — extend it, don't fork it). Never leave a half-applied update.
2. **Never destroy without confirmation.** Deleting a project, contact, event, or (later) a sale/payment requires an explicit confirm step in the UI. Cascades (`on delete cascade` / `set null`) are declared in the schema on purpose — read `supabase/migrations/` before adding a foreign key.
3. **Idempotent inserts.** Any code path that can run twice (auto-generated recurring rows, imports, retries) must be safe against duplicates: use a unique index and handle Postgres `23505` by skipping, never by crashing. `lib/importLocal.ts` (one-time localStorage → cloud import) is the reference: it filters seed rows and clears local keys only after a successful insert.
4. **Money is pure and tested.** When the finance modules land (sales, payment plans, expenses, investments), every derived number (balance owed, plan progress, monthly P&L) comes from a pure helper in `src/utils/` with a vitest test beside it. Denormalized counters are recomputed from raw rows, never incremented in place.
5. **RLS on every table**, `auth.uid() = user_id`, no exceptions. The anon key is public by design; RLS is the security boundary. Service-role keys never appear under `src/`.

If you are about to touch `hooks/useCloudStore.ts`, `context/AppContext.tsx`, `data/rows.ts`, `lib/importLocal.ts`, or anything under `supabase/`, re-read this section first.

# Angus

Mobile-first PWA — a life & business planner for a working artist. **Spanish UI.** TypeScript (`strict: true`, `allowJs: false`), React 19 + Vite 6, custom CSS design tokens (no UI library), Supabase (Postgres + Auth + RLS), Vercel hosting.

Users: each person has their own account and their own **workspace**; data belongs to a workspace, not a user. The artist owns hers; the admin account (`ADMIN_EMAIL` in `src/config/admin.ts`, mirrored by `public.is_admin()`) is implicitly a member of every workspace with full read/write and switches between them from the account sheet (topbar avatar). Roles `owner | admin | member` live in `workspace_members` for future collaborators.

## Product experience standard — what "top tier" means here

These are not aspirations; they are acceptance criteria for every screen.

- **First paint looks like the destination.** Long fetches render a skeleton that mirrors the final layout (`.sk-bar` / `.sk-circle`). Never ship a bare "Cargando…" string.
- **Every tap answers in under 100 ms.** Optimistic updates for all mutations; press feedback on every tappable (`.btn` scales to 0.95 on `:active`, inline tappables get `.btn-tap`). If a write fails, the UI reverts and says so — it never silently swallows.
- **One gesture vocabulary.** Sheets slide up from the bottom and dismiss via handle-drag, overlay tap, the X, or Escape — *not* the OS back gesture, which walks the hash history and changes the screen behind the sheet (`hooks/useEscape.ts` says why that trade was taken). There are no centered lightbox modals. The three daily screens live in the bottom tab pill (Hoy · Agenda · Dinero); everything else is one tap away in the left drawer, and the topbar chevron brings her back. Detail flows open as sheets, not new routes.
- **No dead ends.** Every empty state (`.empty-state`) tells her what the screen is for and offers the next action. Every error state offers a retry.
- **Reads at a glance.** KPI numbers use tabular numerals. Status is carried by color semantics (below), never by color alone — always pair with a label.
- **Works on a phone in a studio.** 44×44 hit targets, 16px minimum input font (no iOS zoom-on-focus), safe-area aware, keyboard never hides the primary button, dark mode automatic, `prefers-reduced-motion` respected, tolerant of a flaky connection (optimistic UI + error toast, never a frozen spinner).
- **Feels alive, not busy.** Motion uses the tokens (`--ease-spring` for surfaces landing, `--ease-out` for everything else, `--dur-*` durations). No animation that doesn't communicate a state change.
- **Spanish, warm, specific.** Copy speaks to *her* ("Tu día", "Sin proyectos todavía — agrega una pieza…"), never generic ("No data"). Money is MXN via `toLocaleString`.

If a change makes the app feel less like this, it's a regression even if the feature works.

## Architecture

- `src/main.tsx` → `App.tsx`. `App` owns auth gating (`hooks/useAuth.ts` → `screens/AuthScreen.tsx`), loads the account's workspaces (`hooks/useWorkspaces.ts`, active one remembered per account), and mounts `context/AppContext.tsx` **keyed on the active workspace id** so a switch remounts the stores. `SignedIn` wraps the screen in `PullToRefresh` → slide-animated wrapper (direction from `BottomTabs.TAB_ORDER`) → `SkeletonCrossfade`.
- **Data flow — one context.** `AppContext` composes nineteen `useCloudStore(workspaceId, …)` instances (projects, contacts, events, sales, payments, installments, expenses, recurring rules, event series, class groups, enrollments, attendance, courses, assignments, notes, note tags, note tag links, note attachments, documents) and exposes typed `items` + `add/addMany/update/remove` per entity, plus `loading`, `error`, `refreshAll`, and the workspace `settings` + `updateSettings`. Screens consume via `useApp()`. Row ↔ entity mapping (snake_case ↔ camelCase) lives only in `data/rows.ts`.
- `hooks/useCloudStore.ts` — generic optimistic CRUD over one Supabase table, filtered by `workspace_id` and stamping it on inserts (see Prime Directive #1). `add`/`addMany` resolve to a boolean so a child row (installment, series, enrollment) is inserted only after its parent landed; `inflight` counts pending inserts so the materializers wait for them.
- **Materializers live in `AppContext`** and run once the stores are loaded and idle: `utils/materialize.ts` turns active recurring rules into Sale/Expense rows keyed by `(recurring_rule_id, period_key)`; `utils/series.ts` turns event series into occurrences keyed by `(series_id, date)`, ~12 weeks ahead. Both are pure, tested, and idempotent (partial unique indexes + `23505` tolerance). Both are also gated: they refuse to run when `canDiff` says a store they read came back partial — a diff against a truncated list is wrong, not stale — and a latched per-session breaker caps how many rounds they may write. `pendingMaterializations` backfills at most `MAX_BACKFILL_PERIODS` (24) per rule, keeping the most recent window and reporting the rest as `deferred`; it used to insert a decade of months on first load for a rule with an old `startDate`.
- `hooks/useWorkspaces.ts` — workspace list, active one remembered per account, `settings` jsonb (`utils/settings.ts::mergeSettings` normalizes it), `onboardedAt`. `components/AccountSheet.tsx` — identity, workspace switcher, sign out. `config/admin.ts` — `ADMIN_EMAIL`.
- `lib/supabase.ts` — the single client instance. `lib/importLocal.ts` — one-shot migration of pre-login localStorage data. `lib/exportCsv.ts` — CSV export. `lib/appearance.ts` — text scale. `lib/api.ts` — `apiFetch` to the serverless routes with the session JWT. `lib/files.ts` — upload pipeline (HEIC → JPEG, ≤ 2048px downscale, XHR progress), cached signed URLs, `StorageError` codes. `lib/notePdf.ts` — a note → PDF (jsPDF, lazy-loaded).
- **Routing** is hash-based (`hooks/useNavigation.ts`). Three routes live in the bottom pill (`home | schedule | money`, `TAB_ROUTES`); the rest are reached from the left drawer (`projects | contacts | classes | studies | notes | expos | recurring | budgets | forecast | reports | settings`). Drawer routes show a back chevron in the topbar (`back()` returns to the parent tab) and fade in instead of sliding. At ≥1024px the drawer becomes a persistent rail. Sheets are component state, not routes.
- **First login** — `workspaces.onboarded_at` null → `screens/Onboarding.tsx` (eight steps, each persisted as it's answered) instead of the app. Everything it collects is a workspace setting (name, practice, mediums, payment defaults, monthly goal, fixed expenses → recurring rules, appearance); Settings → Perfil re-runs any step.
- `screens/` — one file per route plus `AuthScreen` and `Onboarding`. `components/` — sheets (`*Sheet` over the shared `Sheet` + `SheetActions`), pickers (`SegmentedControl`, `ChipSelect`, `ChipMultiSelect`, `PickerField`/`PickerSheet` — **never a native `<select>`**), chrome (`Drawer`, `BottomTabs`, `QuickAddFab`, `PullToRefresh`, `Toast`, `UpdateToast`), primitives (`Icon`, `EmptyState`, `AnimatedNumber`, `LoadingSkeleton`, `ProgressRing`, `SearchField`, `PeriodPicker`, `MonthGrid`, `PlanBuilder`, `charts/BarChart`), the notes family (`NoteEditor` over `notes/*` — `MarkdownEditor`, `FormatToolbar`, `SlashCommandMenu`, `NoteOutline`, `FindInNote`, `VersionHistorySheet`, `NoteTagPicker`, `TagFilterPills`, `NoteLinkChip`, `AttachmentStrip`, `CoverPickerSheet`, `QuickCaptureSheet`), and files (`DocumentList`, `DocumentViewer`, `UploadSheet`, `LinkSheet`). Full catalog with props in `docs/playbook.md` §1.
- `data/constants.ts` — enums with Spanish labels + semantic colors. **Every enum here is mirrored by a check constraint in `supabase/migrations/`** — change both, in the same commit.
- `types.ts` — the domain model. Dates are ISO `YYYY-MM-DD` strings; times are `HH:MM`. Format for display only via `utils/dates.ts`.
- `styles/` — split by concern (`fonts`, `base`, `components`, `money`, `dashboard`, `drawer`, `settings`, `onboarding`, `charts`, `calendar`, `account`, `auth`, `studies`, `notes`, `notes-editor`, `files`, `responsive`, `dark`), aggregated by `index.css`. Keep files narrow.

## Domain model

- **Workspace** — her studio. `settings` jsonb (`WorkspaceSettings`: artist name, practice, mediums, payment defaults, monthly goal, budgets per expense category, theme, text scale, quick actions) and `onboardedAt`. Settings personalize Hoy (greeting, goal ring, which drawer sections show) and pre-fill every sheet.
- **Project** ("Obra") — a piece, commission, or series: `status` (idea / in_progress / on_hold / completed), `availability` (available / reserved / sold / not_for_sale / gifted), medium, dimensions, year, edition, location, start/due dates, price, `cost` (materials estimate), optional linked contact, optional `courseId` ("Para el curso…"), photos via `documents`.
- **Contact** — `relationship` (lead / client / gallery / supplier / collaborator / teacher / school / other / student via enrollments). A teacher's detail sheet lists the courses they teach (Estudios tab). Leads carry a `leadStage` (new / contacted / negotiating / won / lost) and a `followUpDate`; Hoy's attention list surfaces follow-ups due today or overdue.
- **ScheduleEvent** — one unified calendar: `kind` (class / expo / meeting / deadline / personal / other), date, optional times/location, optional project + contact, `budget` (expos). An occurrence of a series carries `seriesId`; `detached` means it was edited alone and regeneration leaves it, `cancelled` keeps the row (hidden) so it never regenerates.
- **EventSeries** — a repeating event: `cadence` (weekly / biweekly / monthly), `weekdays`, times, start/end dates, optional `groupId` when it is a class schedule. Occurrences are materialized ~12 weeks ahead; edits offer "Solo este / Este y siguientes / Toda la serie".
- **Sale** — money owed to her: title, amount, date, `status` (quoted / confirmed / delivered / cancelled), `category` (piece / commission / class / workshop / service / license / grant / other), `paymentTerms` (single / deposit_balance / installments — an intent; the plan itself is the installments), optional project + contact + expo event. Only confirmed and delivered count toward revenue. A sale generated by a rule carries `recurringRuleId` + `periodKey`.
- **Payment** — money actually received against a sale (`saleId`, amount, date, `method`). The source of truth for "paid"; a refund is a deleted payment, never a negative one (`payments.amount` has a `> 0` check). Between cancelling a sale and handing the money back, what she took is reported as `refundable` by `utils/accounting.ts` and shown as "Por devolver" in Dinero — it used to vanish from every total while the payment row stayed in the database. `profitLoss` is cash basis and deliberately does NOT take `sales`, so a status edited later cannot rewrite a closed month.
- **Installment** — one scheduled step of a payment plan (`saleId`, amount, `dueDate`). An expectation, not money: `utils/accounting.ts` allocates the sale's payments across its installments in due-date order rather than storing a "paid" flag that could drift.
- **Expense** — money out: title, amount, date, `category` (16 values grouped Taller / Obra / Ventas / Admin), optional `method`, project and expo event; `recurringRuleId` + `periodKey` when generated.
- **RecurringRule** — `kind` (income / expense), amount, category, `cadence` (weekly / biweekly / monthly / quarterly / yearly) × `interval`, start/end, `active`, optional contact / project / `groupId`. An income rule **materializes a confirmed Sale each period** that she marks as collected (a Payment); an expense rule materializes an Expense. Deleting a rule never deletes the rows it generated (`on delete set null`). Amount edits only affect future periods.
- **ClassGroup** — a class she teaches: name, `seriesId` (its schedule), `tuitionAmount` per student, `tuitionCadence` (monthly / per_session), capacity, location, `active`.
- **ClassEnrollment** — a contact in a group (`startedOn` / `endedOn`), unique per (group, contact). Enrolling with monthly tuition creates an income rule per student (`category: class`, `groupId`), so tuition flows through Por cobrar like any other sale; unenrolling ends the enrollment and pauses the rule.
- **Attendance** — one row per (event, contact): present / absent / excused. Per-session tuition creates a sale per present student, keyed by `periodKey = event id`.

**Estudios — the student side.** Andrea also *takes* classes, talleres, a maestría, seminarios. The teacher module above (ClassGroup) and the student module below coexist; what tells a `class` event apart is `groupId` (she teaches) vs `courseId` (she attends). Both are gated in the drawer by `settings.practice` (`classes` "Doy clases" · `studies` "Estudio / me formo") or by existing rows.

- **Course** ("Curso") — `kind` (class / workshop / master / seminar / diploma / online / other), `status` (upcoming / active / completed / dropped), institution, `teacherContactId`, `modality`, location / URL, dates, `seriesId` (its schedule — occurrences carry `courseId` and a `missed` flag for "Falté"), `cost` + `paymentPlan` (single / monthly / per_session / free) and `recurringRuleId` (the tuition **expense** rule, `category: courses`). Expenses, rules, projects and notes link to a course with `on delete set null`; only its series cascades. `utils/studies.ts` derives cost paid / remaining, next session, tareas pending, spend per course.
- **Assignment** ("Tarea") — `courseId`, title, markdown `description` (task lines drive a progress ring), `dueDate` + optional `dueTime`, `status` (todo / in_progress / done), `completedAt`, optional `projectId` (the piece made for it), grade + feedback. Hoy's attention list surfaces overdue and due-soon ones; Agenda shows due dates as virtual deadline rows (never stored as events).
- **Note** ("Nota") — markdown `title` + `content`, `pinned`, optional links to a course, one of its sessions (`eventId`), a tarea, a piece; `coverAttachmentId`; a generated Spanish `search_tsv`. Unlinked notes are the Inbox. **NoteTag** (per workspace, unique by lower(label)) + **NoteTagLink**. **NoteVersion** rows are written server-side by `snapshot_note` (60 s collapse, 50-version cap) after each autosave; restore keeps the pre-restore text as its own version. **NoteAttachment** — an image in R2 (`r2Path`, mime, size, dimensions) referenced inline as `![](attachment:<id>)`; rows cascade with the note, the bytes are purged first (best-effort).
- **Document** — a file in R2 or a link, attached to a course (Material), a tarea (Entrega), a piece (Fotos) or an event: `kind` file | link, name, `r2Path` / `url`, mime, size, dimensions. The row is inserted only after the PUT succeeded; delete purges R2 then the row.

Derived views — every one takes the dates it works from and reads no clock, enforced by a `no-restricted-imports` rule on `todayISO` in `eslint.config.js` (`dashboard.ts` once accepted a `today` argument and then used `daysUntil()` anyway, which is how the suite came to be asserting against the machine's date). All under `src/utils/`, all tested: `accounting.ts` (balances, plan progress, P&L, income by category, budget progress), `forecast.ts` (6-month projection: committed vs estimated, runway, assumptions), `insights.ts` (period summary, deltas, top clients, medium mix, lead funnel, days to collect), `expo.ts` (budget vs actual, break-even pieces, signal), `classes.ts` (occupancy, attendance rate, tuition status), `studies.ts` (course cost, sessions, tareas due, progress, spend per course), `dashboard.ts` (attention items, goal progress), and the notes helpers `markdownModel.ts` (line model, tokens, transforms), `outline.ts`, `noteDiff.ts`, `noteGrouping.ts`, `noteSearch.ts`, `noteText.ts`.

Not built on purpose (say so in the UI, don't half-build): invoices, push notifications, an offline write queue, multi-currency, bank sync, tax filing, video embeds (links render as links). Notes are plaintext at rest — no clinical data here.

## Database & security

- `supabase/migrations/NNN_*.sql` are the canonical schema; apply them in order and commit the file in the same commit as the apply. Every data table: `id uuid`, `workspace_id uuid` (not null, FK → `workspaces`), `user_id uuid default auth.uid()` (creator), `created_at`, `updated_at` (trigger `set_updated_at`), and one RLS policy for all verbs: `using (is_workspace_member(workspace_id)) with check (is_workspace_member(workspace_id))`. Template in `docs/playbook.md` §5.
- `workspaces` / `workspace_members` (migration 002): `is_workspace_member()` and `is_workspace_admin()` are `security definer` so data policies can consult membership without recursion; `is_admin()` short-circuits both. `handle_new_user` (trigger on `auth.users`) creates each new account's workspace.
- Migrations so far, all applied live: `001_init` (projects, contacts, events) · `002_workspaces` · `003_money` (sales, payments, installments, expenses) · `004_sale_event` · `005_workspace_settings` (`settings` jsonb, `onboarded_at`) · `006_money_model` (sale category + payment terms, 16 expense categories + method, `recurring_rules`, `recurring_rule_id`/`period_key` with partial unique indexes) · `007_event_series` (`event_series`, `series_id`/`cancelled`/`detached` on events, unique `(series_id, date)`) · `008_obra_expos` (inventory fields on projects, `budget` on events) · `009_classes` (`class_groups`, `class_enrollments`, `attendance`, `group_id` on rules and series) · `010_period_keys` (period keys re-keyed to the period, unique `(period_key, contact_id)` for per-session tuition sales) · `011_studies` (`courses`, `course_id` on series / events / expenses / rules / projects, `missed` on events) · `012_assignments` · `013_notes` (`notes` with Spanish FTS, `note_tags`, `note_tag_links`, `note_versions` + `snapshot_note` and `search_notes` RPCs) · `014_documents` (`documents`, `note_attachments`, `notes.cover_attachment_id`) · `015_contact_roles` (teacher / school relationships) · `016_load_indexes` (`(workspace_id, created_at desc, id)` composites for the paged reads, on the growing tables only) · `017_signup_allowlist` (`allowed_signups` + a `before insert` trigger on `auth.users`) · `018_admin_table_and_grants` (`platform_admins` keyed on `auth.uid()`, `search_path` pinned on `is_admin` / `set_updated_at`, the FK indexes that matter) · `019_revoke_definer_from_public` (**wrong — broke the live app**; revoking EXECUTE from PUBLIC on the policy helpers took it from `authenticated` / `anon` / `supabase_auth_admin` too, and an RLS policy is evaluated as the querying role, so every read and write returned `permission denied for function is_workspace_member`) · `020_restore_function_grants` (reverses 019 and documents why the advisor lint is not actionable for a policy helper: the role that needs EXECUTE is the role the lint wants it revoked from) · `021_session_tuition_index` (`sales_session_contact_uidx` now selects rows by the session-uuid *shape* of `period_key` instead of `recurring_rule_id is null` — the old predicate was a property of a row's history, not the row, so `on delete set null` swept every rule-generated sale into it and a second delete raised 23505 *from the cascade*, which the client reads as "already materialized") · `022_materializer_skips` (`materializer_skips` records "this rule, this period, leave it alone", so deleting a rule-generated sale or expense sticks instead of being re-inserted on the next materializer pass; `utils/materialize.ts` is its only reader and nothing derives money from it).

  **A `grant`/`revoke` migration is only verified by re-running the check as the role that will actually run it** (`set local role authenticated;`). Setting `request.jwt.claims` alone leaves the session as `postgres`, which holds EXECUTE on everything — a test that cannot fail is not a test.
- **`sales.period_key` is a union of three shapes**, which is easy to miss: `YYYY-MM` for monthly / quarterly / yearly rules, the ISO Monday `YYYY-MM-DD` for weekly / biweekly, and **a session event's uuid** for per-session class tuition (migration 010). The two unique indexes stay disjoint only because one requires `recurring_rule_id is not null` and the other `is null`. `periodKeyFamily()` in `utils/recurrence.ts` names the first two; editing a rule ACROSS families would bill the same period twice under two different keys, which the index cannot see, so `RecurringRuleSheet` does not offer it.
- Idempotent generators rely on those partial unique indexes: the client inserts what it computes is missing and treats `23505` as "already there, reload". Never add a generator without its index.
- Client-generated ids (`utils/id.ts` → `crypto.randomUUID()`) are inserted as-is so optimistic rows and server rows share an id.
- Auth: email + password and magic link (Supabase Auth). No social providers in v1. Confirmation email goes through Supabase's built-in mailer (rate-limited to a few per hour) — move to Resend SMTP before inviting anyone beyond the two of you.

### The `api/` layer (Vercel serverless) and R2

Files live in Cloudflare R2, never in Postgres. `api/` (own `api/tsconfig.json`, NodeNext, type-checked by `npm run typecheck`, never imported from `src/`) mirrors Cardigan's `_r2.ts` pattern:

- `api/upload-url.ts` → presigned PUT (5 min, MIME allowlist) · `api/file-url.ts` → signed GET (15 min; inline for images/PDF, attachment otherwise) · `api/delete-file.ts` → `DeleteObject`. `api/_cors.ts` allows the production origin, `*.vercel.app` previews and localhost.
- **Authorization without a service role.** Every route verifies the caller's JWT with a Supabase client bound to *that* JWT and selects the workspace — RLS returns the row only for members / the admin. Paths are `ws/<workspaceId>/<cursos|tareas|piezas|sesiones|notas|misc>/<uuid>.<ext>` and `parsePath` (migration-era note: this file used to name a `validatePath` that never existed, and the regex only checked the `ws/<uuid>/` prefix) enforces every segment of it. The tenant boundary is `isWorkspaceMember`, not the path: a member of one workspace can't sign a URL into another because RLS won't return the workspace row. Covered by `src/utils/__tests__/r2Path.test.ts` and end-to-end by `npm run r2:smoke`.
- Env (Vercel Production + Preview, and `.env.local` for `scripts/r2-smoke.mjs`): `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME=angus-documents`, `SUPABASE_URL`, `SUPABASE_ANON_KEY`. **None of these are `VITE_`**; `check-bundle-secrets.mjs` also scans `dist/` for the R2 key values when they're present at build time. The bucket needs a CORS rule allowing `PUT`/`GET` from the Angus origins (the browser PUTs straight to R2).
- Until the env is set the routes answer 503 and the UI shows "Almacenamiento pendiente" instead of a broken upload. `scripts/r2-smoke.mjs` proves the whole leg (upload-url → PUT → file-url → GET → delete) against a deployment with a disposable account.

### Design system (identical to Cardigan — read before building any new screen)

Angus uses Cardigan's design system unchanged: same tokens, same class vocabulary, same chrome. When something looks "off" it's because a screen invented values instead of following these patterns.

- **Typography.** `--font-d` (Nunito) is the *display* face — screen titles, card headers, sheet titles, KPI numbers, button labels. `--font` (Nunito Sans) is body. Sizes come from `--text-xs` 11 / `--text-sm` 12 / `--text-md` 14 (body) / `--text-lg` 16 / `--text-xl` 20 / `--text-2xl` 24. Eyebrows: uppercase, `--text-eyebrow` (10px, never scaled), `letter-spacing: 0.06–0.07em`, weight 700, `--charcoal-md` or `--charcoal-xl`. Display headlines weight 800, `letter-spacing: -0.2 to -0.3px`. Fonts are self-hosted (`public/fonts/`, `styles/fonts.css`) — no Google Fonts `<link>`.
- **Color semantics — pick by meaning.** **Rose (`--accent`) is primary / interactive**: FAB, active tab, links, focus rings and outlines, pressed rows, active chips, progress fills, selected picker rows, input focus borders. `--accent-pale` = active-row / focus backing (`--accent-mist` the lighter pressed tint); **`--accent-dark` is the text step** — any label ON an accent fill, and any accent-colored text (white on `--accent` is only 3.73:1; on `--accent-dark` it's 5.37:1). `--accent` itself is for fills, icons and rings. **Teal is a STATE, never an action**: in progress, confirmed sale, expo, materials — `.badge-teal` and the `*_BADGE` maps only. Neutrals are blush (`--cream` / `--cream-dark` / `--cream-deeper`, `--border` / `--border-lt`) and text is plum (`--charcoal` body, `--charcoal-md` secondary, `--charcoal-lt` tertiary, `--charcoal-xl` meta + eyebrows — the bottom two were darkened to clear 4.5:1 at 10–12px on every blush ground, which is why the ramp's last steps are only ~4 L* apart: this palette cannot hold four distinct text steps all above 4.5:1 on cream) — there are no greys in this palette, so never introduce one (that includes `filter: saturate()` on a charcoal surface). Reserved status colors: red = destructive / overdue / deadline / lost; green = completed / won / success / a positive month; amber = pending / on-hold / prospect / warnings; purple = personal / idea / learning; blue = class / equipment; gray = other / neutral. `--rose` is deliberately unclaimed — it sits ~20° from `--accent` and reads as an accent chip. Use the `--*-bg` companions for tinted panels — never hand-picked rgba. Badge labels mix their hue toward `--charcoal` by `--badge-mix` — **55% in light, 72% in dark** — so 11px text clears 4.5:1 in both themes. The ratio is a token rather than a literal because the two themes genuinely need different amounts: at 72% light, five of the eight lanes failed (amber 3.45:1, rose 3.57, green 4.05, blue 4.33, purple 4.49), while dark was already clear and pulling it further only washes the lanes out.
- **Spacing rhythm.** Card inner padding 14–16px; sheet body 20px h / 20–24px v; rows 12–14px v / 16px h; stack gaps 12 (tight) / 14 (form rows) / 16 (default) / 20–24 (sections). Hit targets ≥ 44×44. `.input-group` already stacks with `margin-bottom: 14px`.
- **Borders, radii, elevation.** `--radius-sm` 8 inputs/chips; `--radius` 12 bands; `--radius-lg` 16 cards + sheets; `--radius-pill` buttons/chips/segments. `--border-lt` dividers, `--border` emphasized. `--shadow-sm` resting cards, `--shadow` lifted, `--shadow-lg` sheets/overlays. **Buttons are pill-shaped, full stop.**
- **Buttons.** `.btn` family only: `.btn-primary` (charcoal fill, primary CTA), `.btn-secondary`, `.btn-ghost`, `.btn-danger`. Disabled = `opacity: 0.55 + cursor: not-allowed`. Active scales 0.95 with `--ease-spring`. Inline tappables get `.btn-tap`.
- **Sheets are the canonical modal.** `.sheet-overlay` > `.sheet-panel` > `.sheet-handle` > `.sheet-header` (`.sheet-title` + `.sheet-close`) > body > sticky footer with `border-top: 1px solid var(--border-lt)`. Wire `useEscape` + `useFocusTrap` + `useSheetDrag`, and gate `safeClose = submitting ? null : onClose` so nothing can dismiss mid-submit. `components/Sheet.tsx` already does all of this — compose it, don't re-implement it.
- **Inputs.** `.input-group` > `.input-label` + `.input`. Hints beneath as `.input-error-msg` (reserved min-height, toggled with `.is-visible`) or `.input-help`. Date/time inputs are native `<input type="date|time">`. Font-size ≥ 16px. Don't add `interactive-widget` to the viewport meta.
- **Cards & rows.** `.card` (white / radius-lg / border-lt / overflow-hidden) before inventing a wrapper. `.row-item` for lists (12px gap, 13/16 padding, min-height 62, `--accent-mist` active). `.kpi-card` for numbers: tabular-nums, eyebrow over a 20–22px display number.
- **Empty states.** `.empty-state` + `.empty-state-icon` (44×44 `--cream-dark` circle, 20px icon) + `.empty-state-title` (font-d 800 `--text-lg`) + `.empty-state-body` (13px `--charcoal-md`, max-width 320) + optional `.empty-state-action` (a `.btn .btn-primary`, width capped). `components/EmptyState.tsx` takes `actionLabel` + `onAction` — pass them whenever the next step is one unambiguous create, and reuse the handler the screen's FAB already calls.
- **Loading.** Skeleton mirroring the final layout, built from `.sk-bar` / `.sk-circle`; paused under reduced motion automatically.
- **Icons.** `components/Icon.tsx`, `currentColor`, sizes 12 / 14 / 16 / 20 (default) / 22 / 36. Standalone icons sit in a 44×44 hit target.
- **Motion.** `--ease-out` default; `--ease-spring` for surfaces landing (sheets, FAB); `--ease-in-out` cross-fades. `--dur-fast` 150 / `--dur-base` 250 / `--dur-slow` 400 / `--dur-slower` 600. No raw cubic-beziers.
- **Safe areas.** Consume `--sat / --sab / --sal / --sar` only — never raw `env()`. Sticky top bars: `padding-top: calc(var(--sat) + 14px)`. Scroll containers reserve `padding-bottom: max(16px, var(--sab))`. `.shell` (fixed, `overflow: clip`) + scrolling `.page` is the layout; every full-viewport surface owns its own scroll container.
- **Scroll surfaces bounce.** `.scroll-bounce` on any non-`.page` scroll container (sheet bodies, auth screen).
- **Dark mode is automatic IF you use tokens.** `dark.css` only flips `--*` variables. Hex literals and inline rgba shadows don't flip — always `--shadow-*`, `--*-bg`, etc.
- **Tabular numerals wherever money or counts are shown.**
- **Liquid Glass is tokenized.** The floating bottom tab pill, FAB, topbar and toasts each consume the `--glass-*` tokens in their own rule in `base.css` / `components.css` — the token is the contract, not a shared class, because those surfaces carry hand-tuned extras (the pill's edge-lens pseudo-layers, the FAB's accent tint). `.glass-chrome|bar|panel|tinted` package the same four grades as utilities for *new* chrome; nothing consumes them yet, so a new floating surface should reach for the class instead of hand-rolling the recipe a fifth time. Never stack two backdrop-filter surfaces; glass is for floating chrome only — cards and sheet panels stay opaque.
- **Drawing outside the lines.** A genuinely new pattern (chart, calendar grid, gallery) ships as a named class in `components.css` or a screen-scoped CSS file, never as an inline-style snowflake.
