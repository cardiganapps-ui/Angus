## The structural defect that explains most of the rest

**Fixes land at the call site, not at the root.** The team diagnoses a bug correctly,
fixes it exactly where it was found, and leaves it standing everywhere else it lives.

- Commit `0cc39f8` "stop claiming a save succeeded before the server answers" fixed
  ~2 sites. **73 fire-and-forget `void add/update/remove(...)` calls across 16 files
  remain**; exactly 2 call sites check the boolean the store returns.
- The cancelled-sale reconciliation was fixed in `totals()` and surfaced in Money.tsx —
  but `incomeByCategory`, `salesByMedium` and `topClients` still drop those payments.
- Route splitting was designed correctly in `App.tsx`, then defeated by static imports
  in two eager edges (`Home.tsx:42`, `AssignmentSheet.tsx:15`).

`useCloudStore` is sound. **The danger is in the 21 files that call it** — its
per-mutation revert can only undo its own call, and cannot compensate a sibling write
that already committed.

## P0 — Before the pilot

### 1. There is no backup. Not "untested" — zero runs. `[checked]`
The GitHub Actions API returns `{"total_count":0}` for `backup.yml`. The secrets are
unset, so it has never executed. There is no PITR (free plan), no soft-delete and no
`deleted_at` anywhere in 20 migrations, and no down-migration. `docs/handoff.md:151`
says it plainly: *"the Prime Directive is uninsured."* The pilot invitation is already
written.

**Fix:** set the secrets, run it, then do an actual **restore rehearsal** into a scratch
project. Note `docs/playbook.md:275` documents `psql -f` without `-v ON_ERROR_STOP=1`,
which exits 0 past every error — the documented restore cannot distinguish success from
failure. Nothing else in P0 matters until this is done.

### 2. R2 objects have no backup path at all `[checked]`
`backup-db.mjs` dumps Postgres and uses `ListObjectsV2` only to prune *its own* prefix.
`exportAll.ts` exports `documents`/`note_attachments` **rows** — the pointers — not the
bytes. No versioning, no lifecycle rule (grep returns zero).

Every photo of her artwork, every note attachment, every course document exists in
exactly one place. For a visual artist's business memory those images are the *most*
irreplaceable data in the system, and they are the only class with zero coverage. The
dump faithfully preserves paths to files that would be gone.

**Fix:** enable bucket versioning + an R2→offsite sync; extend `exportAll` to bundle bytes.

### 3. `canDiff` ignores `readError` — the materializer runs against an empty list `[CONFIRMED]`
`useCloudStore.ts:286` returns early on a read failure, leaving the previous
`truncated`/`coverage` — which on first load is `EMPTY_LOAD` (`truncated: false`).
`canDiff` therefore reports a store that loaded **zero rows** as complete. If the `sales`
read alone fails, the money materializer diffs against nothing and inserts phantom sales.

**Fix:** make `canDiff` fail closed on `readError`.

### 4. Compound flows destroy data on partial failure `[CONFIRMED / PLAUSIBLE]`
- `EventSheet.tsx:215` "Este y siguientes" fires `updateSeries` (truncate),
  `removeEvents` (delete ~12 future sessions) and `addSeries` (the replacement) as three
  **unordered `void` writes**, then unconditionally toasts success. A rejected
  `addSeries` leaves the class deleted with nothing left to regenerate it.
- `EventSheet.tsx:181` "solo este" — same shape; a failed insert erases the session and
  strands its attendance rows.
- `AppContext.tsx:684` `removeCourse` purges R2 bytes *before* the revocable row delete.
- `AppContext.tsx:609` — **ten `remove*` wrappers** call `dropLocal` after an
  `await x.remove(...)` whose result they cannot see (`deleteRows` returns `void` on both
  paths), so a *rejected* delete leaves the parent restored and its children erased
  locally, inflating "Por cobrar".

**Fix:** make `deleteRows` return a boolean; gate every `dropLocal` on it; sequence and
check the compound flows; purge bytes only after the row delete succeeds.

## Product judgment

The engineering bar is high. The *aim* is the problem: 14 destinations, 20 entities,
24 tables, and a hand-rolled markdown editor with version history, FTS, PDF export and
inline attachments — for **one user**, with an 8-step onboarding wizard for someone
sitting next to the developer. The repo even ships `src/lib/usage.ts`, an instrument
built to discover which routes she never opens; a top-1% team makes that call *before*
shipping fourteen destinations.

The cost is legible in this list: the notes subsystem (~4.5k lines) is the largest thing
in the repo and drives findings #14, #18 and the bundle regression — while the tenant
boundary (#11) and the rollback path (#12), the two things the Prime Directive names as
existential, went untested and unbacked-up. That is a prioritization error, not a craft
error, and it is the single most investable thing to change.
